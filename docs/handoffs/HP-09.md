## HP-09: Mutator first slice, model-independent fixes (the MAS-1 open decisions)
**Owner:** Misty (she owns the Mutator code) · **Size:** S · **Depends on:** nothing (D-M1, D-M2, D-M3 settled 2026-11-25) · **Phase:** A
**Spec:** `docs/MUTATOR_PLAN.md` sections 4, 6, 14. Files: `public/node-graph-pitch-mutator-overlay.js`, `public/pitch-mutator-engine.js`, `native_modules/graph_engine/graph_engine.cpp` (`process_pitch_mutator`, ~7318), `scripts/test_pitch_mutator_engine.mjs`.

**Decisions settled (2026-11-25).** D-M1 (Argi: "yes"): ignore the second armed knob for now. D-M2 (Argi: "yes"): a wired Freq In drives the playhead; unwired falls back to the audition key. D-M3 (Argi: "yes"): an empty Frequency lane passes the incoming frequency through; make JS agree with native.

**Goal.** Fix only what is independent of the gradient merge so the shipped slice is correct while gradients are built. **Do not** add multi-lane, inspection view, native offsets or polyphony here (HP-10/11/12 will redo them on the gradient model).

**Scope.**
1. **Second armed knob turn (D-M1, settled: ignore).** Today `bindKnob()` returns `state.lanes[0]` when a lane exists, so a second armed turn writes into lane 1 and overwrites that slider (overlay.js ~174 to 255). **Ignore** a second knob while a lane exists (return `false` from `applySliderIntercept`, leave the knob free, show one plain info line in the overlay: "One knob lane for now"). Do not add a second lane in this handoff (HP-10 will rebase on the gradient model).
2. **Freq In drives the playhead (D-M2, settled: yes).** When the Mutator's Freq In is wired, `soundingNote()` (and so `applyLiveParams`, `applyToBase`, Pin, Auto-Pin) must use the incoming frequency (`69 + 12*log2(f/440)`), read as a continuous signal; unwired falls back to `ui.auditionNote`. Do it without timers: derive from the existing live-param / signal update events (`hookMidiKeyboard`, `scheduleNodeGraphLiveParameterSync`).
3. **Empty Frequency lane passes through (D-M3, settled: yes).** Native already passes the input frequency through when there are no keys; make the JS side agree (`freqAt` returns null → pin writes `hzFromNote`; confirm Freq Out display and `playheadHz` behave) and add the case to the engine test.
4. **Remove the perpetual `requestAnimationFrame` loop (policy violation; confirmed in MasterBot's HP-02 review, 2026-11-25).** `tick()` in `public/node-graph-pitch-mutator-overlay.js` (lines 915–928) re-runs **every frame forever**, including when the overlay is closed: it always calls `injectCommandCenter()`, `hookNav()`, `hookMidiKeyboard()` (re-checks the monkey patch of `sendNodeGraphLiveMidiKeyboardSignal`), and `refreshRings()`, then does `ui.raf = root.requestAnimationFrame(tick)` at line 927 (only the plot redraw at lines 919–925 is gated on `ui.open`). `boot()` (lines 946–953) starts the loop at line 952. Argi's 2026-11-24 rule is event-driven only (a rAF loop is OK only while work is queued). Replace with: one-time inject/hook at boot (or on the Command Center / nav re-render event), redraw on overlay open, on audition-note change, on pin/lane change, on selection and patch-commit events (use `addNodeGraphPatchCommitListener`), and a rAF that runs only while a redraw is queued. Also review the `viewSaveTimer` `setTimeout` (line 385): a one-shot save debounce on an event is acceptable, but say so in the report.
5. **Velocity-height check (D-M4 research only).** Verify, in a Metamodule with a Voice Gate, whether Voice Gate carries height = velocity per `docs/GATES_TRIGGERS.md` (lines 34, 78). Write the finding into `MUTATOR_PLAN.md` section 14 (docs only). No Velocity lane yet.
6. Add tests to `scripts/test_pitch_mutator_engine.mjs` for 1 to 3 (and a headless check that no `requestAnimationFrame` is scheduled while the overlay is closed and idle).
7. **Overlay keyboard changes the playhead on pointerdown** (Argi t412u, 2026-11-25). Today the strip keys (`data-pm="key"`) are handled in `onOverlayClick` (`click` listener at line 336, handler lines 742–744), so the audition note and `playheadHz` update on pointerup. `onAxisPointerDown` on a key (lines 482–484) only starts `maybe-key` pan detection and does not call `setAuditionNote`. Change the key/pitch (audition note and playhead) on pointerdown. Keep the existing pan-vs-tap threshold (8px at lines 507–510, `suppressKeyClick`) so dragging still scrolls the strip. Do **not** add Gate/Freq audition output here — that is HP-12 (see note below).

**Note (Argi t412u, 2026-11-25): overlay keyboard sends no Gate.** Verified in `public/node-graph-pitch-mutator-overlay.js`: a strip key only calls `setAuditionNote` (updates `ui.auditionNote` and `node.params.playheadHz`). There is no write to Gate Out and no audition gate/freq signal from the strip. Native Gate In/Out is pass-through only. This is **explicitly deferred to HP-12** (`docs/MUTATOR_PLAN.md` later phase / HP-12: "audition from the overlay keyboard via Gate/Freq outs"). Not in HP-09 scope. First-slice tapping is only meant to set the audition note / playhead (plan section 7).

**How to set up a knob lane** (put these steps in the HP-09 report for Argi; the overlay help line at 688 only says "Arm, then turn one knob to bind," which is incomplete). The flow is not broken, but it is easy to miss, and a bind with Auto-Pin off does not start mutating until you pin:
1. Add a Pitch Mutator. Open the Mutators overlay and select that Mutator's tab. Arming only works while the overlay is open (`isArmed()` requires `ui.open`).
2. Press **Arm**, then turn one canvas knob (not a knob on the Mutator itself). `bindKnob` (lines 174–193) creates a lane with `keys: []` and a chip/ring should appear. Auto-Pin is off by default.
3. With Auto-Pin off, `applySliderIntercept` (lines 236–242) **returns false** when the lane has no keys, so further turns write the base slider instead of the lane until you pin. Set the playhead (strip key, or a wired Freq In once D-M2 lands), press **Pin Keyframe**, move to another note, turn the bound knob (or edit the offset), **Pin Keyframe** again. Or turn **Auto-Pin** on before editing the bound knob at each note. Wire Freq Out into a FREQUENCY input to hear the frequency lane. Only one knob lane in this slice (D-M1).
HP-09 may also extend that help line so it mentions Pin Keyframe / Auto-Pin.

**Acceptance criteria.** Second armed turn no longer changes lane 1 or the first knob; a played note on a wired Freq In moves the playhead and knob offsets live (verify in the browser with the on-screen keyboard wired to Freq In; report what you saw); an unkeyed Frequency lane emits the input Hz in both JS and native; all engine tests pass; no `requestAnimationFrame` scheduled while the overlay is closed and idle (idle CPU shows no per-frame work from the Mutator); the overlay strip key/pitch changes on pointerdown (playhead and audition note update immediately; a drag that becomes a pan still does not fire a click); the report gives Argi the exact knob-lane setup steps above; `?v=` bumped.
