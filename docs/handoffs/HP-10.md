## HP-10: Stage A5, rebase the Pitch Mutator onto gradients
**Owner:** Misty · **Size:** L · **Depends on:** HP-03, HP-04, HP-09; Argi decisions **D-M5, D-M6, D-M7** · **Phase:** D · **Unblocks:** HP-11, HP-12
**Spec:** plan section 5 (Gradients plan), `docs/MUTATOR_PLAN.md` sections 3, 6, 8, 10.

**Goal.** One data model. A Mutator knob lane **is** a gradient; the Mutator becomes an axis-to-position router. The Frequency lane stays on the Mutator (Hz is not a slider offset).

**Scope.**
- Mutator binding = `(gradient id, axis, position curve)`; axis = pitch (0..127 from Freq In or the audition key). The curve maps axis to position 0..1 reusing the Step Graph shapes (`nodeGraphSegmentCurve01`); default map per D-M5 (recommended: linear over MIDI 0 to 127, stored on the Mutator binding, not the gradient). The Mutator's contribution adds to the gradient position (clamped 0..1), per Gradients plan 4.5.
- **Pin Keyframe / Auto-Pin** now writes a **stop** at the position the current note maps to, into the Mutator-owned gradient (D-M6 recommended: snapshot all moved sliders; the overlay still highlights the active param). Arm + knob turn registers the param into the gradient (this also resolves D-M1 option "add a second param").
- The overlay's lane plot reads the gradient's stops as a function of pitch (offset curve per param, one active at full strength, others faint), so the relation-on-one-keyboard view of the Mutator plan survives.
- Mutator-owned gradients appear on the Gradients page flagged with the Mutator's name (D-M7).
- Remove the Mutator's private knob-lane code and its own offset path from the overlay/engine once the provider list handles it (delete, do not keep both). Keep: overlay UI, MIDI policy, Freq lane + native LUT, view persistence, rings/chips, `remapLaneTargets`/`dropMissingTargets` equivalents for gradients.
- **Migration:** shipped patches have **no** authored knob-lane data (`patches/acoustic/bass*.json` have 0 lanes). Add a one-way normalize that converts any existing `node.mutator.lanes[]` with keys into a Mutator-owned gradient (write the test with a synthetic fixture); then delete the old fields on next save. Update `MUTATOR_PLAN.md` and `MODULE_GRADIENTS_AND_PRESETS_PLAN.md` to the single model.

**Acceptance criteria.** Sound with a keyed knob lane is unchanged vs before the rebase (A/B by effective-param diff for a fixture with 2 pins); play note, tweak, pin at two pitches, hear the morph; patch reload restores identical behavior; the Mutator's gradient is listed on the Gradients page and edits there move the Mutator's behavior consistently; tests: engine tests updated, `test_gradients.mjs` extended with an axis-driven position case; plugin-host effective params include the Mutator contribution; no timers; `?v=` bumped.
