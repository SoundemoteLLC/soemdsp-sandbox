## HP-06: Stage B1, the variations store (server, catalog script, client wrapper)
**Owner:** Moth · **Size:** M · **Depends on:** nothing (D-P1 settled 2026-11-25) · **Phase:** A · **Unblocks:** HP-07, HP-06b
**Spec:** `docs/MODULE_GRADIENTS_AND_PRESETS_PLAN.md` sections 7.1 to 7.4, 12 (B1), 13.

**Decisions settled (2026-11-25).** D-P1 overrides the roadmap default: KEEP bank/program. **D-P4 (t449u):** "remind me to restart the server when it is needed" — the implementing AI does not restart the server; it must state the exact words **server restart needed** in its report, and Badger reminds Argi when this lands. **D-P2 (with HP-07):** the store/list exposes factory vs user source so the Explorer can treat user presets exactly like factory ones, organized seamlessly, with a visible user-preset indicator and a Factory / User / Both filter; only the save location differs. Bank is a category encoded in the filename (`bankNNN-programNNN-<title>.json`), not in bank subfolders. Program is the actual preset. One single flat folder for patches that go together (no folder diving). Variation names keep the full stem (the autogenerated look is desired, so it is clear they are generated).

**Goal.** A safe file API for **presets and variations** on the dev server / standalone app, plus the factory catalog change and a pure-JS client wrapper. No UI.

**On-disk layout (decided, D-P1 2026-11-25).** One flat folder (today: `saved-patches/`). No bank subfolders. The preset filename stem is `bankNNN-programNNN-<title>`:
```
bank000-program003-Bass.json
bank000-program003-Bass__variations/
    bank000-program003-Bass__Bright.json
    bank000-program003-Bass__1.json        (auto-numbered when no name)
```
Folder `<stem>__variations/`, file `<stem>__<name>.json`, where `<stem>` is the full `bankNNN-programNNN-<title>` stem (variation names keep that full stem). Display name = everything after the **first** `__`. A variation is a **complete patch file** (`format.kind: "soemdsp-sandbox-node-patch"`); loading it is a full patch load. Names: no `\ / : * ? " < > |`, no control chars, no `..`, trimmed, max 64 chars, no Windows reserved names, **case-insensitively unique**; no name = next unused whole number, natural-sorted. Untitled patches get `Untitled 1`, `Untitled 2`, ... (case-insensitive among user presets); **Save is never disabled**.

**Endpoints (`server.py`; the client never sends a path, only `base` stem and `name`; reuse `validate_node_patch_payload`, `server.py:~1009`, and the overwrite `expectedMtimeMs`/`expectedSize` check from `/api/patches/overwrite`).**
- `GET /api/variations?base=<stem>` list (`{name, source, bytes, modifiedUtc}`; user folder plus the shipped folder for a shipped base, a user variation wins on the same name).
- `GET /api/variations/file?base=&name=`.
- `POST /api/variations/save` (auto-number when no name; refuse an existing name unless `overwrite=1` with the baseline check).
- `POST /api/variations/rename`, `POST /api/variations/remove`.
- `POST /api/patches/rename` and `POST /api/patches/remove` for user **presets**; renaming a preset renames its `__variations` folder and the file prefixes **in the same call** so the pair never splits; removing a preset removes its variations folder.
- **Today** (`server.py`, around lines 427 to 551 and 833 to 860) the API is `/api/patches`, `/meta`, `/file`, `/save`, `/overwrite` over flat `saved-patches/` with `bankNNN-programNNN-<title>.json` names. **Keep that filename stem and the single flat folder** (D-P1). Do not introduce bank subfolders, and do not drop the bank/program prefix.

**Factory catalog.** `scripts/rebuild_page_patches_index.py` builds `patches/index.json` for root plus one folder. It must **skip any `*__variations` directory** as a catalog folder and add `variations: ["Bright","Dark","1"]` to the base's entry (so the Explorer can show a count without another request). Check `scripts/prepare_page_patches.py` if it reads the folders. Factory variations need no server change (static files).

**Client wrapper.** New `public/node-graph-preset-store.js`: pure functions around fetch, no DOM, no timers: list presets (factory index + `/api/patches`), list variations, save preset, save variation, rename, remove, load text. Hosted/static site: **load-only** (hide save/rename/remove; no IndexedDB presets).

**Security acceptance.** Fuzz the name/base inputs (`..`, absolute paths, `CON`, trailing dots/spaces, mixed case duplicates, 65-char names, control chars): every one is rejected or sanitized and **never writes outside `saved-patches/`**.

**Acceptance criteria.** A Python test (e.g. `scripts/test_variations_api.py` against a temp dir) covering save / auto-number / overwrite conflict / rename / remove / preset rename moving the folder; `rebuild_page_patches_index.py` run on a temp copy shows `variations` arrays and no `__variations` folder entries; existing `/api/patches*` behavior unchanged; report must include the exact words **server restart needed** (D-P4); do not restart the server yourself. Badger reminds Argi when this lands.

## HP-07: Stage B2, the Preset Explorer UI
**Owner:** Misty · **Size:** L · **Depends on:** HP-01, HP-06 · **Phase:** B · **Unblocks:** HP-08
**Spec:** plan sections 8.1 to 8.3, 8.6, 12 (B2), 13, 14.

**Goal.** The 📄 Command Center page becomes the Preset Explorer: one searchable list of factory and user presets with folders for variations. A DOM menu panel (same status as the paper-page panel it replaces).

**D-P2 (decided t449u).** User presets are treated exactly like factory presets and organized with them seamlessly. The only differences: a different save location, a visible indicator that a row is a user preset, and a filter for Factory / User / Both.

**Layout.** (1) **Search** (text filter on name, folder, author, nothing else). (2) **3-way switch Both / Factory / User** (D-P2). (3) **One list**, folder-style: factory (from `patches/index.json`) and user (from `/api/patches`) organized seamlessly and interleaved by name; each row has the name, a visible user/factory indicator, a small thumbnail placeholder, and a ▶ (preview only in HP-08; ▶ never loads the live patch). (4) A preset with variations is a **folder** you open; children are its variations with the same row anatomy. (5) Buttons: **Save Preset, Save Variation** (two separate buttons), **Load, Remove, Rename**. The app's main save button does **not** change.

**Behavior.**
- Tapping a row only **selects** it.
- **Load** and **overwrite** (Save onto an existing file) use an inline confirm on the same button ("Confirm Load" / "Confirm Overwrite") that clears on selection change, panel close, or commit **events, never a timer**. Before a Load call `recordNodeGraphHistory()` so one Ctrl+Z restores the previous patch. Load goes through `commitNodeGraphScript(text)` (= `commitNodeGraphPatch(loadNodeGraphPatchFromScript(text), {status})`); the commit listener wakes everything. Do not pass `resetEditorView` (framing is the Patch View box's job; `frameNodeGraphPatchViewAfterLoad` already handles it).
- **Save Preset** writes the live patch as a user preset (overwrite if a user preset is selected; `Untitled N` if unnamed). **Save Variation** writes the live patch as a variation of the selected/open parent (auto-numbered if no name; parent becomes `Untitled N` first if unnamed). Factory rows are read-only: Remove/Rename disabled, Save Preset offers "Save as user preset".
- **Remove** deletes a user preset and its variations folder (confirm) or a variation (confirm). **Rename** renames a preset with its folder together, or a variation.
- Hosted/static site: **load-only** (hide Save, Remove, Rename). Plugin: full, via HP-06b.
- After a load: `setNodeGraphCurrentSavedPatch`, `nodeGraphRefreshServerPatchFileBaseline`, `syncNodeGraphHeaderPatchTitle` (as the normal load flow does).
- Phone-friendly: one column, 44 px rows, ▶ is a 44 px target, no hover, no `title=`.

**Files.** New `public/node-graph-preset-explorer.js`; uses HP-06's `node-graph-preset-store.js`; entries in `node-graph-unified-window.js` / `node-graph-floating-windows.js` (the `pages` registry entry now points at the Explorer); `index.html`, `perform.html`, `styles.css`.

**Acceptance criteria.** Browse factory + user together; the 3-way switch filters; search filters; open a folder; Save Preset / Save Variation round trip to disk and appear in the list; Load is one confirm + one undo step; Remove/Rename keep preset and variations folder together; hosted build shows no write buttons; Argi's retest list includes "load a patch with gradients (HP-04) and see them restored". `?v=` bumps; no timers.
