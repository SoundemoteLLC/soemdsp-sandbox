# HP-22: One debug window on G

## Problem
Pressing **G** opens the old "evidence" / other debug window. The main CPU/RAM/GPU debug window doesn't toggle with G.

## Goal
- **G** toggles the main CPU/RAM/GPU debug window, and only that one.
- Remove the evidence window. If anything in it is still useful, move it into a collapsible subsection (sub-window or tab) inside the main debug window. Drop anything that's redundant or dead.
- There must be no second floating debug window left.

## Rules
- Don't worry about legacy compatibility. The app is still in heavy development.
- Events only, no timers or polling. If the panel already samples stats, keep its existing mechanism.
- No hover tooltips, no hand cursor, and labels must stand on their own. Keep the low-clutter UI.
- Report what you kept, what you moved, and what you removed.

## Also in this round: sincos negative amplitude bug
- If sincos Amplitude is set to -0.5 (or any negative value), the display correctly inverts, but the audio treats it as 0 amplitude (silence).
- Fix it so a negative amplitude outputs the inverted signal at that magnitude, matching the display.
- Find where the value gets clamped to 0 or rectified (DSP, wasm bridge or reader). The param definition is the only source of limits, so don't hardcode clamps.
- If the wasm changes, say so, so the 8766 server gets restarted.

## Also in this round: category-tile drag bug (moved from S-4)


Argi: "when i drag out a module from the category (so not actually going into oscillator category and dragging out a dsf oscillator, but dragging from the categories list a DSF oscilltor from dragging the oscillator category), it correctly drags out and places a DSF oscillator but it then goes into the cateogry, it is treated like a click and a click drag at the same time i guess"

**Where.** Category tiles are built by `createNodeGraphModuleDepartmentButton` in `public/node-graph-module-store.js:5224`. The tile's `click` handler (`5234-5237`) calls `setNodeGraphModuleStoreDepartment` and opens the category. Default module types live on `nodeGraphModuleStoreDepartments[].defaultModule` (Oscillator → `dsfOscillator` at `249`) and are resolved by `nodeGraphModuleStoreDepartmentDefaultModules` / `nodeGraphModuleStoreDepartmentDefaultModule` at `4589-4609`.

The drag is in `public/node-graph-module-actions.js`: `nodeGraphModuleStoreDragSlopPx` (`1182`, 6 px); `beginNodeGraphModuleStorePointerPlacement` (`1184-1234`) arms a drag from `[data-store-department]` and uses those default types; `spawnNodeGraphModuleStorePlacementIfDragged` (`1237-1260`) starts placement once movement passes the slop; `releaseNodeGraphModuleStorePointerPlacement` (`1395-1429`) opens the category on pointerup when the gesture never became a drag (`1411-1418`, because pointerdown `preventDefault` can swallow the click on touch). After a real drag that places a module (`1423-1429`), the following `click` on the department button is not suppressed, so the category still opens.

**Fix.** Once a drag passes the threshold and places the module, suppress the click so the category does not open. Events-only, no timers. A plain click (or a press that never crosses the slop) must still open the category.

**Acceptance.** A browser test where a real drag from a category tile places the default module and the store stays on the category list, and a plain click still opens the category. No tooltips, no timers.
