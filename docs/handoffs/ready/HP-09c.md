## What a pin is (plain words, for Argi)
A **pin** is a saved answer to: "when *this note* is playing, the knob should be *here*." You play C4, set Cutoff where you want it for C4, tap **Pin Keyframe**: the Mutator remembers "C4 → that cutoff". Play C6, set Cutoff somewhere else, pin again. Between pins the Mutator slides the knob along the curve you see in the plot; before the first pin and after the last one it holds. After that you stop touching the knob: whatever note arrives on Freq In, Cutoff follows by itself, and the knob on the module should move with it. **Auto-Pin** just means "every time I turn the knob, pin at the note that is playing right now", so you do not have to tap Pin Keyframe each time.
**The dot you saw is not a pin.** It is the Mutator-colored ring (`refreshRings`, line 914) that marks "this parameter is wired to the Mutator". Today it lands on the parameter's small input/output port buttons at the module edge, not on the knob, and nothing draws a pin at all (the plot only draws the curve, no dots). So there was nothing on screen that said "armed", "bound" or "pinned".

## Root causes (reproduced in a real browser page, Chrome headless, real mouse on the real canvas widget; file:line at `22ee8943`)
Repro: `showNodeGraphModule("pitchMutator")` + `("flowerChildFilter")`, `togglePitchMutatorOverlay(true)`, real mouse click on Arm and Auto-Pin (both did flip: `aria-pressed="true"`, `autoPin: true`), then a real mouse drag on the Cutoff widget of the Flower Child face (`nodeGraphModuleFaceWidgets` hit point).
1. **The intercept never engages on a real knob (the main failure).** `applySliderIntercept` (overlay.js 307-312) reads the node id from `slider.dataset.node`. The real range input (`node-graph-module-face.js:397-399` `nodeGraphModuleFaceInput`, same element the ghost sliders use) has `dataset.param` but **no `dataset.node`**; the node id lives on the parent `.dsp-node` (`syncNodeGraphPatchParameterFromSlider`, `node-graph-slider-dragging.js:134`, uses `slider.closest(".dsp-node").dataset.node`). So line 312 returns `false`, nothing is bound, nothing is pinned, and the drag writes the base param normally. Measured: armed + Auto-Pin on + real drag moved Cutoff 0.5 → 0.77 and left `node.mutator.lanes` = `[]`. The HP-09 test passes only because its stub slider is `{ dataset: { node, param } }` (`scripts/test_pitch_mutator_engine.mjs` ~249), a shape the real UI never produces. This is why Arm "does nothing" and Auto-Pin "can't pin".
2. **Even with a node id, lane edits are written to a stale copy.** `ensureState` (overlay.js 46-52) replaces `node.mutator` with `normalizeMutatorState(node.mutator)` (`pitch-mutator-engine.js:147-162`), which builds **new lane objects** every call. `bindKnob` (262-290) returns a lane from one copy; `applySliderIntercept` then calls `selectedNode()` / `ensureState(node)` again (317, 322) and edits `lane.keys` (330, 336) on an object that is no longer in `node.mutator`. Measured with the node id patched in: armed + Auto-Pin on, real drags at C4 and C6: lane created, base untouched (so the intercept returned `true`), but `keys: []` after every drag; nothing is ever stored, so nothing can move. Same for the "shift whole lane" path (336) and `boundLaneFor` (297-305). The Pin Keyframe / Offset field paths work only because they re-read `state.lanes` after one `ensureState`.
3. **Pin Keyframe stores the wrong value.** `pinActiveLane` (229-260) finds the knob with `document.querySelector('[data-node="…"][data-param="…"]')` (245-247). On the real page the first two matches are the parameter's **port buttons** (`.node-param-port.modulation-input`, `.node-param-port.parameter-output`), not the range input. Their `.value` is `""`, `Number("")` is `0`, so "shown value" = 0 and the pin offset is `0 − base` (253-254). Measured: knob at 0.68, Pin at C5 stored offset −0.68, so the effective Cutoff became **0** at every note (`applyNodeGraphParamOffsets` live value 0). That is the dot that "did something" Argi could not read. `refreshRings` (914-933, selector 923-925) has the same wrong element: it rings the port buttons and the hidden input, never the face widget, so the knob itself shows nothing.
4. **Auto-Pin OFF can never produce two different values.** Empty lane + Auto-Pin off: `bindKnob` creates the lane, then 332-338 `else return false` (no keys) drops the intercept and the knob writes the **base** param. Pin then stores `shown − base` = 0 (or, with root cause 3, −base). With keys and Auto-Pin off, a knob turn shifts **every** key by the same delta (332-336), so pinning a second note records the same value as the first. "Nothing moves together" follows. (The plan, `MUTATOR_PLAN.md` line 31, promises "play a note → pin → play another note → pin".) HP-09's test covers only Auto-Pin ON (`test_pitch_mutator_engine.mjs` ~247-260).
5. **Offsets are clamped as if they were 0..1.** `shiftOffsets` (`pitch-mutator-engine.js:321-325`) uses `clampSlider` (289-296), which clamps to 0..1, but offsets are signed (the plot maps `(off + 1) * 0.5`, overlay.js 693; a pin can store −0.68). Any shift turns a negative offset into 0.
6. **Armed state is easy to lose.** `isArmed()` (292-295) is true only while the overlay is **open** *and* `node._mutatorArmed` is set. Close the overlay (to reach a node under it; it covers the bottom 260 px) and Arm is silently inert. Arm (822-826, session flag, not saved) and the Arm button (759) show only a color change; there is no text saying armed / bound / pinned.
7. **Freq In does not reach the native playhead.** `playheadHz` is written only in `setAuditionNote` (203-217, lines 209-210). `soundingNote` follows Freq In / MIDI, but `applyLiveParams` (352-361) keeps `params.playheadHz` once it is finite, so the native path (`node-live-audio-worklet-native-graph.js` 8231-8233, `_mutatorFreqLut` 8660-8662) reads a stale playhead when Freq In drives the note.
8. **D-M1 is silent when the overlay is closed.** `bindKnob` 270-276 returns `null` for any other knob once a lane exists and shows "One knob lane for now" only in the overlay.

Confirmed fine (do not rework): clicks on Arm and Auto-Pin do register; the HP-02 provider list **does** carry the lane to the live params once keys exist (order 20, `registerNodeGraphParamOffsetProvider` at overlay.js 1057-1062; `applyNodeGraphParamOffsets` at `node-graph-live-plan-runtime.js:192, 333` returned the lane value for Flower Child `frequency`).

## Intended UX (recommended defaults; Argi can veto when he retests)
- **D-M8 Arm.** Arm stays on while the overlay is closed, until a knob is bound or Arm is turned off. It **auto-disarms after the first bind** (one knob lane, D-M1). It is shown in the overlay (text) and on the Mutators nav / Command Center button while closed. It is a session flag (not saved) and says so only if asked; do not add hover text.
- **D-M9 Auto-Pin OFF.** With a lane bound, a knob turn is always taken (never falls through to the base write while a lane exists). Auto-Pin **off**: the turn sets a **pending value at the playhead** (the knob shows it); **Pin Keyframe** commits that pending value as a key at the playhead; moving to another note without pinning drops the pending value and the knob goes back to what the lane says for that note. Auto-Pin **on**: each turn pins at the playhead straight away. (This replaces "shift the whole lane on every unpinned turn", which is what made two pins identical. If you still want a whole-lane shift, use the Offset field in the overlay; do not add a modifier key.)
