## HP-18: Module IO labels in the compact view
**Owner:** big AI · **Size:** S · **Depends on:** HP-09c, HP-09b, HP-03 (queued after those three, in that order; no parallel work) · **Phase:** A
**Paste-ready path:** `docs/handoffs/ready/HP-18.md`

**Goal.** In IO View A (the default compact view: one pill per side in the strip between the title and the display), show a short IO label that follows Argi's four rules. View B (Tab: every jack and its full name) stays as it is.

**Why now.** Argi (t425u, 2026-11-25) asked for this as a new handoff. No existing HP covers module port / IO labels (HP-00..HP-17, including HP-09b/c and HP-06b, were checked). Today the compact-view label is blank at all times, which matches what he sees.

**Argi's rules (verbatim, t425u):**
- if a module has only 1 input and or 1 output show the io label, example `📺`
- if a module has more than 1 io and nothing is connected, leave label blank (it's blank right now at all times)
- if a module has more than 1 io and and only 1 thing is connected, show the label of the 1 thing that is connected, for example `⎍`
- if a module has more than 1 io and more than 1 thing is connected, show the first io label and then a comma and then a number for how many mre things are connected, for example `⎍, 1`

Apply each rule **per side** (the left input pill and the right output pill are separate). "1 input and or 1 output" means: a side with one jack always shows that jack's label, even with no cable. A side with more than one jack is blank until something is connected. The number after the comma is how many *more* connections there are (connected count minus one), so two connections render `⎍, 1`.

## Where the code is
View A / View B live in `public/node-graph-io-view.js`. View A is the default (`VIEWS.A`, lines 27, 33): `pills: true`, `labels: "off"`. `nodeGraphIoViewLabelText` (151-152) returns `""` whenever labels are off, so every compact-view label is blank. That is the "always blank" Argi is looking at. View B sets `labels: "full"` and shows every jack name; do not change that.

The pills and their labels are drawn in the GL graph (do **not** edit GL files; see Scope):
- `nodeGraphGlGraphIoPills` (`public/node-graph-gl-graph.js` 2108-2141): one pill per side in the strip, with `count` (how many jacks on that side) and `connected` (whether any jack on that side has a cable). Comments at 1089-1090 and 2110-2111 say the count is kept only so a one-jack side can start a wire, and is **not drawn**. A leftover hitbox in `node-graph-io-view.js` 170-173 is "the strip inward of it (where a count used to be drawn): … nothing is drawn there."
- `pushPill` (1089-1105) stores `{ id, io, x, y, r, count, connected }`. `nodeGraphGlGraphDrawPill` (2232-2238) draws only the connected-state dot, no text.
- Per-jack `.node-io-label` elements are collected at 1028-1046, then skipped when that jack lives in a pill (`nodeGraphGlGraphIoPillPoint`, 1034 and 2143-2147). `nodeGraphGlGraphDrawLabels` (2463-2481) would draw remaining label text, but it always runs the string through `nodeGraphIoViewLabelText` (2469), which blanks it in View A.

Labels come only from the port definitions (plus the existing display helpers, not invented glyphs):
- Module definition `inputs` / `outputs` (and `dataInputs`) via `nodeGraphPatchNodeInputPorts` / `nodeGraphPatchNodeOutputPorts` (`public/node-graph-parameter-metadata.js` 267-301, 304-). That list is the definition order.
- Visible text from `nodeGraphPortDisplayLabel` (`public/node-graph-module-factories.js` 75-96): `inputLabels` / `outputLabels` on the definition, or the port id, then the existing gate/trigger, thru-pair, frequency, and stereo helpers. `nodeGraphPatchNodePortDisplayLabel` (98-147) may apply a port alias or a named-portal / metamodule override. `createNodeGraphIoColumn` (196, 209-216) writes that string onto `.node-io-label` (rgba ports use `nodeGraphPaintRgbaPortLabel`).
- A cable is "connected" when the jack has the `connected-port` class (`node-graph-gl-graph.js` 2133-2135; set in `node-graph-port-geometry.js` ~151, cleared in `node-graph-wire-rendering.js` ~306).

## Decisions (Open; only Argi's own words close them)
- **D-I1.** Separate labels per side, or one shared label for the whole module? Recommended default: **separate**. One label on the left pill (inputs) and one on the right pill (outputs), each following the four rules for that side. This matches the pills that already exist.
- **D-I2.** When more than one jack on a side is connected, what is "the first io label"? Recommended default: the label of the **first connected** jack in port definition order (`nodeGraphPatchNodeInputPorts` / `nodeGraphPatchNodeOutputPorts`), then `, ` and the number of other connections on that side.
- **D-I3.** Does this apply only to View A, with View B still showing every jack's full name? Recommended default: **yes**, View A only.

Build those defaults. Argi can veto them when he retests; leave the register Open until he answers.
