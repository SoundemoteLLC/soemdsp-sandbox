## Root cause (file:line at `6afa3e9b`)
Argi did **not** Arm-bind the Mutator's own frequency parameter. `bindKnob` already returns `null` when the knob is on the Mutator itself (`public/node-graph-pitch-mutator-overlay.js` 364-368: `if (node.id === nodeId) return null`). The Pitch Mutator module has no visible frequency param; its only parameter is hidden `playheadHz` (`public/node-graph-module-definitions.js` 11165-11175).

`bindKnob` already sets `activeLane` to the new knob lane (`L1`) at overlay.js 388 when a knob is first bound. The failure is **Pin Keyframe, or the Frequency Hz field, while Frequency is still the active lane**: either the overlay was just opened (default `activeLane` is `"freq"`, `pitch-mutator-engine.js` `normalizeMutatorState` 158; the Frequency chip starts selected, overlay.js 851), or the Frequency chip was clicked later (`onOverlayClick` 968-970). `pinActiveLane` (337-347) writes `freqLane` keys (Hz at the playhead) whenever the active lane is `"freq"`. The Frequency Hz number field does the same on change / Auto-Pin (1002-1016). Binding Cutoff later does not remove those Frequency keys, and `drawPlot` (806-815) still draws a dot for every `freqLane` key next to the Cutoff pins.

A related gap: turning an already-bound knob goes through `bindKnob` 370-371 (`if (existing) return existing`) and **does not** set `activeLane`. So after the Frequency chip is selected, a bound-knob turn leaves Frequency active, and a following Pin can still write `freqLane`.

Once `freqLane` has keys, Freq Out is no longer an empty-lane passthrough (D-M3). A keyboard (or anything else) on Freq In still moves the playhead (`soundingNote` / `incomingHz`, 108-126) but no longer drives the outgoing frequency, which matches "frequency is not changing" with the keyboard plugged in. There is no disabled / "driven by Freq In" state today: the Frequency chip, the Hz field, and Pin Keyframe all stay live.

The dots he cannot drag are `.pm-pin` circles in the overlay SVG (806-823). They have no pointer handlers (axis pointer code only pans and plays keys). CSS also turns hits off: `.pm-pin { pointer-events: none; }` (`public/node-graph-pitch-mutator.css` 297-298).

The extra "Mutators" button above the Command Center is `injectCommandCenter` (overlay.js 1066-1092): it inserts `#pitchMutatorCcToggle` / `#pitchMutatorCcButton` (a text `pm-btn`) into `#nodeSceneContextMenu`. The unified emoji nav already gets a Mutators control from `hookNav` (1094-1121), but that button's `textContent` is `navLabel()` — `"Mutators"` or `"Mutators (armed)"` (280) — not an emoji. The other pages use `config.icon` as the button text (`public/node-graph-unified-window.js` `buildNodeGraphUnifiedWindowNav` 1455-1478, `node-unified-window-nav-button`).

## Scope
1. **The Pitch Mutator's own frequency / pitch is never bound or pinned.** Keep the `bindKnob` self-id guard; also ignore `playheadHz` and any other self frequency/pitch key even if the id check were bypassed. The Frequency Hz field must not write `freqLane` keys. The status line explains it in words. No tooltips.
2. **When a knob lane exists, `activeLane` defaults to it when the overlay opens.** Turning a bound knob re-selects its lane (today 370-371 returns the existing lane without setting `activeLane`; fix that).
3. **Pin rule.** Frequency is never a pin target. With a knob lane bound, Pin Keyframe always commits that knob lane (even if the Frequency chip is showing, or was just clicked). With no knob lane bound, Pin is disabled and the status line says why (for example: "The Pitch Mutator's frequency cannot be pinned. Bind a knob on another module (Arm, then turn it)."). The Hz field never writes `freqLane` keys. This replaces "disable Pin while the Frequency chip is selected".
4. **When a cable is connected to the Freq In jack**, the Frequency chip, the Hz field, and any Frequency edit show a disabled / "driven by Freq In" state in words, use the existing disabled / under-construction styling (`.node-under-construction-control` in `public/styles.css` 3977-3996, `disabled` / `aria-disabled`), and are not editable. This applies only to a cable into Freq In, **not** to the audition key or the MIDI keyboard. Empty-lane passthrough (D-M3) remains the Freq Out behaviour. Events only: update when a cable is attached or removed, not on a timer.
5. **Recover already-pinned Frequency lanes** in saved patches (Argi's included). Drop `freqLane.keys` **once per load or patch**, not on every `ensureState` call. Show a one-shot status note (for example: "Dropped a Frequency pin. The Pitch Mutator's frequency is not pinnable."), with no timer. Do not silently keep a lane that can no longer be edited, and do not touch a bound knob lane.
6. **Pin dots on the knob-lane plot are interactive.** Keys store **signed slider offsets**. A vertical drag edits the **effective param value** and clamps it to that parameter's definition min/max only, then stores `offset = slider(value) − slider(base)`. Do not use the −1..1 offset clamp as the drag range. A horizontal drag changes the note. The hit target is at least **44 px** (the visible pin stays `r=3.5`). Turn on pointer events for `.pm-pin`. Delete uses one single-action, touch-friendly gesture (see D-M10). No `title=`, no hover text, no arrow cursors (APP_POLICY §24); if a drag cursor is needed, use the shared mouse-dot path. Keep pan / key / 8px threshold working (a pin drag is not a pan). No GL file edits: the dots already live in the overlay SVG.
