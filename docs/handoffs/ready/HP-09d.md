## Root cause (file:line at `6afa3e9b`)
Argi did **not** Arm-bind the Mutator's own frequency parameter. `bindKnob` already returns `null` when the knob is on the Mutator itself (`public/node-graph-pitch-mutator-overlay.js` 364-368: `if (node.id === nodeId) return null`). The Pitch Mutator module has no visible frequency param; its only parameter is hidden `playheadHz` (`public/node-graph-module-definitions.js` 11165-11175).

`bindKnob` already sets `activeLane` to the new knob lane (`L1`) at overlay.js 388 when a knob is first bound. The failure is **Pin Keyframe, or the Frequency Hz field, while Frequency is still the active lane**: either the overlay was just opened (default `activeLane` is `"freq"`, `pitch-mutator-engine.js` `normalizeMutatorState` 158; the Frequency chip starts selected, overlay.js 851), or the Frequency chip was clicked later (`onOverlayClick` 968-970). `pinActiveLane` (337-347) writes `freqLane` keys (Hz at the playhead) whenever the active lane is `"freq"`. The Frequency Hz number field does the same on change / Auto-Pin (1002-1016). Binding Cutoff later does not remove those Frequency keys, and `drawPlot` (806-815) still draws a dot for every `freqLane` key next to the Cutoff pins.

A related gap: turning an already-bound knob goes through `bindKnob` 370-371 (`if (existing) return existing`) and **does not** set `activeLane`. So after the Frequency chip is selected, a bound-knob turn leaves Frequency active, and a following Pin can still write `freqLane`.

Once `freqLane` has keys, Freq Out is no longer an empty-lane passthrough (D-M3). A keyboard (or anything else) on Freq In still moves the playhead (`soundingNote` / `incomingHz`, 108-126) but no longer drives the outgoing frequency, which matches "frequency is not changing" with the keyboard plugged in. There is no disabled / "driven by Freq In" state today: the Frequency chip, the Hz field, and Pin Keyframe all stay live.

The dots he cannot drag are `.pm-pin` circles in the overlay SVG (806-823). They have no pointer handlers (axis pointer code only pans and plays keys). CSS also turns hits off: `.pm-pin { pointer-events: none; }` (`public/node-graph-pitch-mutator.css` 297-298).

The extra "Mutators" button above the Command Center is `injectCommandCenter` (overlay.js 1066-1092): it inserts `#pitchMutatorCcToggle` / `#pitchMutatorCcButton` (a text `pm-btn`) into `#nodeSceneContextMenu`. The unified emoji nav already gets a Mutators control from `hookNav` (1094-1121), but that button's `textContent` is `navLabel()` — `"Mutators"` or `"Mutators (armed)"` (280) — not an emoji. ## Scope

3. **Pin rule.** Frequency is never a pin target. With a knob lane bound, Pin Keyframe always commits that knob lane (even if the Frequency chip is showing, or was just clicked). With no knob lane bound, Pin is disabled and the status line says why (for example: "The Pitch Mutator's frequency cannot be pinned. Bind a knob on another module (Arm, then turn it).").
