## HP-03: Stage A2, gradient data and engine effect (no UI)
**Owner:** Moth · **Size:** M · **Depends on:** HP-02 · **Phase:** B · **Unblocks:** HP-04, HP-05, HP-10
**Spec:** `docs/MODULE_GRADIENTS_AND_PRESETS_PLAN.md` sections 4.1 to 4.6, 12 (A2).

**Goal.** `patch.gradients` exists, round-trips through save/load/undo, and changes effective param values through the HP-02 provider list. Headless-tested. No page yet.

**Data model (authoritative; see plan 4.1 for the full schema).** `patch.gradients = [{ id, name:"Gradient N", enabled, position (0..1), origin:{nodeId:{paramKey:slider01}}, stops:[{pos, offsets:{nodeId:{paramKey:slider-offset}}}], ... }]`. Offsets are in **slider space** (fraction of the parameter's slider travel), stored relative to `origin`.

**Behavior to implement.**
- **Sum:** `finalSlider = clamp01(baseSlider + sum(enabled gradient offsets) [+ later Mutator offsets])`, then the definition's slider curve and min/max map to the domain. The clamp comes only from the parameter definition. `node.params` (the base) is **never** rewritten. Gradients never read their own output (snapshots read base only).
- **Interpolation:** linear between stops by `position`; **hold** the end values outside the end stops (decided for v1).
- **Morphable predicate:** continuous numeric params interpolate. Params with `choices`, on/off switches, and integer-step params without choices (Seed, step counts) **snap at the halfway point** (`t = (pos-posA)/(posB-posA)`; `t<0.5` keeps stop A, else B; two stops at one position switch hard). **Not gradient params:** Step Graph / Smooth Graph points, `stepRegister`, `chordMemory`.
- **Capture helpers (pure functions the page will call in HP-04):** `createGradientFromSnapshot`, `snapshotIntoGradient(gradient, position)` (registers every param whose base slider differs from `origin` by more than 1e-4 of slider travel; a param first moved at a later stop gets implicit zeros earlier; re-snapshot on an existing stop replaces it), `setStart` (re-record origin), `dropAllZeroParams` (a param whose offset is zero at every stop is removed automatically).
- **Robustness:** at apply time, **skip** missing node ids / param keys without crashing and without rewriting the stored list (the duplicate/delete rule D-G1 is decided later).
- **Persistence:** normalize + serialize in `public/node-graph-patch-core.js` (next to where HP-01 removed the circuit-patch fields) and `public/node-graph-patch-serialization.js`; include in `nodeGraphPatchFingerprint` exclusions per plan 11.6 (gradients excluded). Patches without `gradients` load unchanged. No `patch.format` bump needed (additive field).
- **Events only:** position or stop changes call the existing live-param update path (`scheduleNodeGraphLiveParameterSync`, `sendNodeGraphLiveParameterUpdate`). No timers.
- New file `public/node-graph-gradients.js` (model, capture, provider) registered as a provider ahead of the Pitch Mutator.

**Acceptance criteria (`scripts/test_gradients.mjs`, headless, must pass).**
1. Two enabled gradients on one param add; a disabled one is ignored.
2. The sum is clamped by the definition's min/max for a normal slider **and** a `nonlinearSlider` param.
3. Choice, switch and integer-step params snap at halfway; hard switch at equal positions.
4. The base `node.params` is unchanged after apply, after save/load round trip, and after undo.
5. A snapshot registers only moved params; an all-zero param is dropped; a later-stop param gets implicit zeros earlier.
6. A gradient that references a deleted module/param applies without throwing and the stored list is unchanged.
7. Hold outside the end stops.
8. Plugin-host effective params include the gradient offsets (reuse the HP-02 test hook).
Plus: load every file under `patches/` and `saved-patches/` and confirm no diff in effective params (no gradients present).
