## HP-04: Stage A3, the Gradients page
**Owner:** Misty · **Size:** L · **Depends on:** HP-01 (empty broom shell), HP-03 · **Phase:** C · **Unblocks:** HP-05, HP-10 (HP-14 is later plans, t449u)
**Spec:** `docs/MODULE_GRADIENTS_AND_PRESETS_PLAN.md` sections 4.2, 4.8, 4.9, 12 (A3), 13.

**Goal.** The old broom page (🧹, `patchDefaults`, `#nodePatchDefaultsPanel`) becomes the **Gradients page**, the **only** gradient UI in the app. A DOM menu panel (allowed), phone-friendly, no GL work.

**Scope.**
- Top: optional filter **All / Touching the selected module** (updates on selection events; no polling). A **Snapshot** button starts a new gradient from the current bases (name `Gradient N`, next unused N).
- One **card per gradient**: editable name (Rename); a **strip** about 44 px tall full width, 28 px handles, a white playhead, number labels staggered on alternate stops, background a `linear-gradient` through one hue per stop (`hsl(order*137.5, 55%, 50%)`). Tap empty spot = add stop (snapshot of current bases) there; drag a stop to move it; drag anywhere else to move the playhead. **Each release records one undo step** (`recordNodeGraphHistory()` before the commit), never per pointer-move.
- Buttons: **Snapshot, Delete stop, Rename, Delete gradient, Set start**. Registered-param rows `Module · Param` with the offset at the playhead as a plain number (`+0.12`). **No remove (✕) UI.** The line `Holds still: Step Graph` is HP-05.
- Enabled toggle, so a gradient can be turned off (needed later by Gradient to Module).
- Wire `node-graph-module-actions.js` (bind the page on open) and `node-graph-history.js` (re-render the page after undo).
- New `public/node-graph-gradient-page.js`; script tags and panel markup in `public/index.html` and `perform.html`; `public/styles.css`.
- **D-G1 (decided t449u, "yes"):** delete drops that module's params from every gradient (one undo step with the delete); duplicate does not copy into gradients; no dangling refs are saved. Keep HP-03's skip-missing behavior at apply time; persist the drop when the module is deleted. A short clickable prototype is optional for teaching the rule, not for reopening the decision.

**Rules.** No `title=`, no hover-only actions, 44 px rows, no timers (do not reuse `confirmNodeGraphDefaultButtonClick`), no edits to MasterBot's files; use `nodeGraphGlGraphNoteValueChrome(id)` after a position change so GPU sliders repaint. **D-G5 (decided t449u, "yes"):** in the DAW plugin the Gradients page is shown (offset editing is not a topology edit); only Gradient to Module is hidden there (HP-14, later plans).

**Acceptance criteria.**
- Create a gradient from a snapshot, move two sliders on two different modules, snapshot again: both params register. Drag the playhead: sliders' effective values (and the audio, via a running Comb Resonator or similar) glide; base slider values in the saved patch never change.
- Save, reload, undo/redo: strips, stops, names, positions restored. A position drag is exactly **one** Ctrl+Z.
- Rename, Delete stop, Delete gradient, Set start, enabled toggle all work and are undoable.
- Choice/switch params snap at halfway while dragging.
- Works at phone width (rows >= 44 px, no hover), and in `perform.html`.
- Headless test or Playwright smoke for the page's create/snapshot/undo cycle; Argi retest checklist in the report.
